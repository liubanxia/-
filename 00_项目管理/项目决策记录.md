# Project Phoenix 项目决策记录

文档版本：V1.0.0  
建立日期：2026年8月6日  
项目名称：离线AI-PACS智能辅助阅片系统  
项目代号：Project Phoenix  

---

## 决策001：采用完全离线运行架构

**状态：** 已确认  
**决策内容：**

医院正式运行环境不得依赖外网、云端模型或在线API。

**原因：**

1. 医院电脑可能无法访问外网。
2. 医疗数据不得上传到公共网络。
3. 离线架构更利于隐私保护和稳定运行。
4. 系统必须在网络中断时继续工作。

---

## 决策002：采用“手机＋SSD＋Windows电脑”工作模式

**状态：** 已确认  
**决策内容：**

```text
手机负责联网下载
→ SSD负责承载工程和更新包
→ Windows电脑负责离线开发与运行
决策003：SSD作为项目核心载体

状态： 已确认
决策内容：

SSD保存：

* 开发环境；
* 源代码；
* AI模型；
* 医学知识库；
* 规则库；
* 经验库；
* 配置；
* 日志；
* 构建版本；
* 备份。

补充要求：

开发SSD与医院生产SSD必须分离。
决策004：一个医院使用一套独立生产SSD

状态： 已确认
原因：

不同医院的PACS界面、报告格式、规则、术语和运行环境可能不同，必须独立配置和验证。
决策005：生产SSD不得进入网吧

状态： 已确认
原因：

防止患者信息泄露、恶意软件污染、配置破坏和医院数据外流。

网吧只能使用开发SSD，并且只能处理公开资料或已脱敏资料。
决策006：V1.0只支持普通CT平扫和常规DR

状态： 已确认
暂不支持：

* 增强CT；
* CTA；
* MRI；
* 超声；
* PET/CT；
* 病理图像。

原因：

先缩小临床范围，完成安全、稳定、可验证的第一版系统。
决策007：医生拥有最终决定权

状态： 已确认
决策内容：

AI只能提供候选征象、分析建议、鉴别诊断和报告草稿。

AI不得：

* 签署报告；
* 审核报告；
* 发送报告；
* 删除病例；
* 删除报告；
* 绕过医生确认。
决策008：系统同一时间只处理一个病例

状态： 已确认
原因：

避免病例串线、报告写入错误患者及自动化误操作。

病例身份不确定或发生切换时，系统必须立即停止。
决策009：不得建立包含患者真实姓名的长期数据库

状态： 已确认
决策内容：

真实姓名、身份证号、住院号、检查号等身份数据，只能在当前病例处理期间临时使用。

任务结束后应按规则清理。

经验库、测试库和证据中心只允许保存脱敏数据。
决策010：病灶截图必须由医生主动确认

状态： 已确认
流程：
AI完成报告草稿
→ 询问医生是否标注病灶
→ 医生选择“是”
→ AI截取关键层面并标注
未经医生确认，AI不得自动保存病例截图。
决策011：正确病例的临时截图原则上删除

状态： 已确认
决策内容：

如果AI结论正确且医生没有修改相关内容，临时截图在完成核查后删除。

如果医生修改了相关结论，截图经脱敏后可作为错误分析证据。
决策012：医生修改必须进入反思学习流程

状态： 已确认
分析内容：

1. 医生修改了什么。
2. 为什么修改。
3. AI属于漏诊、误判、定位错误还是表达错误。
4. 哪一条规则没有正确执行。
5. 是否存在相似历史错误。
6. 如何形成学习文档。
决策013：AI不得自行把经验升级为正式规则

状态： 已确认
决策内容：

AI只能生成：

* 候选经验；
* 候选规则；
* 候选纠错建议。

正式规则必须经过医生确认后才能进入规则库
决策014：PDF资料采用本地检索增强方式使用

状态： 已确认
决策内容：

PDF书籍、指南和医院规范导入本地知识库后，通过检索定位相关章节，为报告审核和错误分析提供依据。

禁止：

未经验证直接使用PDF资料自动修改模型权重。
决策015：采用CPU优先的轻量化模型架构

状态： 已确认
原因：

目标医院电脑可能只有普通CPU和有限内存。

系统应采用：

* 模型按需加载；
* 多模型串行调度；
* ONNX Runtime；
* 轻量OCR；
* 资源限制；
* 空闲时学习处理。

不得影响PACS正常操作。
决策016：固定医学分析流程

状态： 已确认
流程：
解剖定位
→ 病变识别
→ 技术前提确认
→ 客观征象描述
→ 性质判断
→ 鉴别诊断
→ 规范化报告
CT判读必须先确认窗宽窗位。

平扫CT不得描述强化表现。

不得编造测量值、CT值和未显示征象。
决策017：采用模块化单体架构

状态： 已确认
原因：

V1.0需要降低部署复杂度，同时保留后续扩展能力。

系统先采用模块化单体结构，核心模块之间通过明确接口通信。
决策018：所有重大修改必须进行Git提交

状态： 已确认
要求：

每次重大修改必须：

1. 更新相关文档。
2. 更新开发日记。
3. 更新项目决策记录。
4. 完成测试。
5. 完成Git提交。
6. 保留可回退版本。
决策019：未经模拟PACS测试不得接触真实PACS

状态： 已确认
原因：

避免未经验证的鼠标、键盘和界面识别操作影响真实临床工作。

所有自动化操作必须先在模拟PACS中测试。
决策020：安全优先于开发速度

状态： 已确认
决策内容：

任何功能如果不能确认病例身份、操作目标、医学依据或安全边界，必须停止执行，而不是猜测或继续运行。
